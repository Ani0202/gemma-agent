I recommend **M2 as the next landing experiment**, but its checkpoint is model-triggered, not structurally scheduled. The plan should distinguish that experiment from a guarantee.

Consequently, a bundled Python checkpoint helper is legitimate. A bundled Python callback imported into the harness is not supported.

**4. M3 cannot turn the existing submission tool into a guarded operation.**

`get_status` returns:

`status`, `tool_calls_used`, `patch_submitted`, `patch_size`, and—when configured—`tool_calls_remaining`, `max_tool_calls`, `time_seconds_remaining`, `max_time_minutes`, `agent_elapsed_seconds`, `max_turns`, and `command_timeout_seconds`.

**Its patch fields describe the submitted snapshot, not current workspace modifications.** Before submission, `patch_size=0` can coexist with a valid live source diff. It supplies no changed-file list, source classification, or remaining-turn count. See [execution.py:119](/home/ubuntu/gemma-local/venv/lib/python3.13/site-packages/swegemma/tools/execution.py:119).

`submit_patch` obtains the diff, strips protected files, then **unconditionally stores the result and sets `patch_submitted=True`**. Empty results—including a diff emptied by stripping tests—are accepted. That flag disables fallback collection. A skill can refuse its **own preflight**, but cannot prevent the model from calling the separately exposed `submit_patch`. Removing `submit_patch` from every agent’s tools is expressible and prevents premature snapshot capture, but still cannot create a missing edit. Tool exposure comes from each agent’s declared list: [llm.py:62](/home/ubuntu/gemma-local/venv/lib/python3.13/site-packages/adk_submission/builders/llm.py:62).

**5. The two additional controls**

**A single `run_command` below the configured 60 seconds: FEASIBLE through its shell command.** There is no per-call timeout parameter—the exposed signature accepts only `command`. Wrap the entire operation, including pipelines:

```bash
timeout -k 1s 15s /bin/bash -c 'set -o pipefail; pytest tests/test_target.py -x -q 2>&1 | tail -30'
```

This requests termination at 15 seconds and forced termination one second later. The Docker backend itself uses `timeout`, establishing its availability there. The harness also automatically reduces command timeouts near the session deadline. See [execution.py:148](/home/ubuntu/gemma-local/venv/lib/python3.13/site-packages/swegemma/tools/execution.py:148), [docker.py:703](/home/ubuntu/gemma-local/venv/lib/python3.13/site-packages/swegemma/sandbox/docker.py:703), and [execution.py:31](/home/ubuntu/gemma-local/venv/lib/python3.13/site-packages/swegemma/tools/execution.py:31).

**Another numeric total-output cap per turn: NOT FEASIBLE.** `max_output_tokens` is the supported total generation limit. `thinking_budget` is separately expressible and forwarded as a thinking-specific backend setting; it is not another total-output cap. Stop sequences can terminate generation but provide no numeric bound. See [schema.py:202](/home/ubuntu/gemma-local/venv/lib/python3.13/site-packages/adk_submission/schema.py:202) and [generation.py:434](/home/ubuntu/gemma-local/venv/lib/python3.13/site-packages/adk_submission/resolvers/generation.py:434).

**The strongest case against my proposed M2 choice:** it leaves the critical decision—*invoke the edit now*—with the same model that already ignored the early-edit instruction. Skill invocation adds argument-generation and execution overhead, and the model must still supply a useful replacement. It could merely produce wrong non-empty patches, improving the landing metric without improving pass rate. Plan 005 already acknowledges that distinction at [005.md:67](/home/ubuntu/work/gemma/eval/plans/005.md:67).

**Recommendation: choose M2 for the next screen, explicitly as risk reduction.** Use one model-invoked Python skill that validates and applies the current best replacement, confirms a live source diff, and becomes a no-op when such a diff already exists. Trigger it immediately when a plausible replacement exists, with call/time checks as backstops. Do not describe it as an automatic checkpoint or a universal timeout guarantee.
