## Environment (dec 034 item 6 / dec 058 item 7: which env the local sandbox models, and why)
Docker-path emulation of Dockerfile.public (dec 027, the plan-006 kernel stack, setup_fix=1): editable install + test deps from the
offline /wheels via the harness setup.py into the sandbox venv; verification = the stock swegemma verify_task (Container B: fresh
sandbox, agent patch with test/config files stripped, hidden test_patch applied, pytest on the target test files, resolved = exit 0).
Why this env and not H1 (test deps from the scorer notebook's site-packages): (1) the clean list (48) and dev split were calibrated
with gold and null patches in this same docker-path emulation (results/gold_calibration_per_task.jsonl), so "dev task is solvable"
is only defined here; (2) no H1 gold calibration exists, so an H1 pass rate could not separate agent failures from env failures;
(3) the agent-side env is the same one all plan-005/006 screens used. Known gap: if the scorer runs H1, some tasks may pass or fail
differently from the scorer for env reasons (sign unknown). Follow-up, not part of this plan's runs: a CPU-only Kaggle gold+null pass
of the 33 dev ids through the same kernel verification path (and, separately, an H1 variant) to measure the env-disagreement rate.

## Decision rules
- ARM 1 alone is a measurement: no ship decision follows from it. It sets the baseline for arm 2 and is cited in the dec 061 (i)
  v004 cap discussion. If the primary is 0/33 with harness errors on >= 5 tasks, arm 1 is INVALID (env problem), not a quality result.
- ARM 2 vs ARM 1 (paired, same 33 ids, k=1): discordant counts on-only / off-only, exact two-sided sign test.
  Adopt thinking ON if on-only > off-only with p < 0.2 AND on has no more timeouts than off + 2 AND a cap-3.5 timing check passes;
  adopt OFF (keep default) if off-only >= on-only; otherwise (on ahead, p >= 0.2) NO-DIFFERENCE: keep OFF (cheaper, faster), and k=2
  for both arms only if quota allows (a second seed per arm, same rule on the pooled pairs). +-3 tasks on 33 is noise.
- Cost note: verification adds a fresh sandbox setup per task (Container B, two dependency installs), so per-task wall is higher than
  the plan-005 screens (~5.5 min/task); the smoke measures it. If arm 2 at k=1 does not fit next week's quota with other approved work,
  the arm-2 schedule comes back to the Director with the measured numbers.
